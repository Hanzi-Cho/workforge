사람은 자고 있다. 아침에 이 문서를 읽고 "이 계획대로 구현을 시켜도 되는지" 판단할 것이다.

## 대상 이슈

```json
__ISSUE_JSON__
```

__REPO_SECTION__

## 네가 채울 것

아래 4개 절만, 이 순서대로, 이 제목 그대로 출력한다.
**다른 것은 아무것도 출력하지 마라** — 머리말, 코드펜스로 전체 감싸기, "알겠습니다" 전부 금지.
스크립트가 이 출력을 문서의 정해진 블록에 그대로 끼워넣는다.

```
## 이슈 해석

Jira 원문이 실제로 요구하는 것을 네 말로 다시 쓴다.
원문이 애매하면 애매하다고 쓴다. 추측으로 메우지 마라.

## 코멘트

이 이슈에 대한 기술적 의견. 다음을 포함하라(해당되는 것만):
- 이게 왜 발생하는지에 대한 가설과 그 근거
- 이슈 자체의 문제(재현 조건 누락, 기대 동작 미정의, 중복 이슈 가능성)
- 함께 고쳐야 할 것 / 같이 깨질 것 같은 곳
- 우선순위에 대한 의견

## 수정 계획

1. …
2. …

단계별로. 각 단계가 무엇을 바꾸는지 구체적으로.
검증 방법도 마지막 단계에 포함하라.

## 확인 필요

- 사람이 결정해야 하는 것
- 정보가 없어 진행할 수 없는 것

Confidence: 0.0~1.0
Recommendation: READY_TO_IMPLEMENT | NEEDS_DECISION | NEEDS_MORE_INFO | NOT_ACTIONABLE
```

## 금지 사항

- **본문이 없는 이슈에 그럴듯한 분석을 만들어내지 마라.**
  제목만 있으면 `Recommendation: NEEDS_MORE_INFO` 로 하고,
  "Jira 에 무엇을 채워야 하는지"를 구체적으로 적어라. 그게 이 경우의 정답이다.
- 확인하지 않은 파일 경로나 줄번호를 쓰지 마라.
  아침에 사람이 클릭해서 없으면 이 문서 전체의 신뢰가 사라진다.
- 원인을 모르면 "원인 미확정"이라고 써라. 그럴듯한 추측이 가장 비싼 실패다.
- 테스트를 돌렸다거나 실기에서 확인했다고 쓰지 마라. 너는 실행할 수 없다.
