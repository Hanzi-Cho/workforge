# 업무 온톨로지와 n8n 실행 계약

**모델의 근거.** 사용자가 확인한 Jira·메일·전화·대면 문의, Jira 중심의 추적, 매일 쓰는 Confluence 업무일지와 기존 Workforge 검증·검토·학습 후보 계약에서 도출한 초안이다. 공유 Claude 아티팩트 원문은 로그인 화면으로 접근이 제한되어 원문 모델과의 일치 여부는 미확인이다.

각 `work.route.v1` 출력의 `ontology` 필드는 `work.ontology.v1` 그래프 한 조각이다. 문의에서 나온 근거가 어느 사건에 속하는지, 검증과 사람이 남긴 검토가 같은 산출물 버전을 가리키는지, 일지의 각 행이 어느 사건의 근거를 인용하는지 추적한다. n8n에서 사용하는 JavaScript 함수와 로컬 라우터가 동일하다. 실행에는 모델 호출이나 외부 서비스 계정이 필요하지 않다.

## 식별과 출처

| 필드 | 해석 |
| --- | --- |
| `classification` | 검증된 입력의 `synthetic` 또는 `personal`. 식별 검증 이전에 거절한 입력은 `unclassified`. |
| `provenance` | 라우팅 스키마, 기존 출력 키, 허용된 원본 이벤트 종류. 식별이 불가능한 키와 차단된 이벤트의 종류는 `null`. |
| `nodes[]` | 각 노드는 `id, type, label`을 갖는다. ID는 `유형:분류/식별자/…`이고 각 식별자 조각을 URL 인코딩한다. |
| `edges[]` | `id, from, type, to`를 갖는다. 양 끝은 같은 조각 안에 있는 노드다. ID는 관계 종류와 양 끝의 ID로 결정한다. |

한 분류 안에서 사건은 `case_id`, 이벤트는 `event_id + revision`, 산출물은 `case_id + artifact_id + artifact_revision`으로 식별한다. 근거·검토 참조·게이트는 사건 단위의 참조 이름을 사용한다. 일지 행은 날짜가 같은 다른 일지와 구분되도록 일지 이벤트 버전과 0부터 시작하는 입력 행 번호로 식별한다. 화면용 레이블에는 1부터 번호를 표시한다. Jira의 기존 티켓 키는 여러 사건에서 같은 키를 참조할 수 있다. 학습 후보는 사건, 완료 이벤트 버전, 학습 항목 ID에 귀속된다.

예를 들어 `evidence:synthetic/file-import/fixture-replay`는 검증 완료 이벤트와 일지 행이 사용하는 동일 근거다. `evidence:synthetic/other-case/fixture-replay`는 다른 사건의 근거다. 서로 다른 출력 그래프의 노드와 관계는 ID로 합칠 수 있다. 각 이벤트의 출처는 해당 출력의 `provenance`에 보존한다. 정렬 결과는 실행 시간·입력 객체의 필드 순서에 의존하지 않는다.

## 이벤트와 관계

| 원본 이벤트 또는 결과 | 생성하는 관계와 의미 |
| --- | --- |
| 공통 | 이벤트가 사건에 연결되고(`about_case`), 라우팅 결과를 만든다(`yields`). 결과에서 목적지(`routed_to`)와 판정(`disposition`)을 읽는다. 실제 저장·게시 시점은 목적지 영수증으로 확인한다. |
| `issue.received` | 신고된 채널 → 이벤트(`received`), 이벤트 → 접수 근거(`cites`), 근거 → 결과(`supports`). 기존 키를 제공하면 결과 → 기존 티켓(`refers_to_ticket`). 예전 입력에서 생략된 채널은 미기록으로 둔다. |
| `work.completed` | 이벤트 → 대상 산출물 버전(`concerns_artifact`), 이벤트 → 확인 게이트(`at_gate`), 이벤트 → 검증 참조(`cites`), 참조 → 검증한 버전(`verifies`). 학습 근거가 있으면 TIL 후보 결과와 학습 항목을 연결한다(`describes_learning`). |
| `review.decided` | 이벤트 → 사람이 남긴 검토 참조(`cites`), 참조 → 검토 대상 버전(`reviewed_artifact`). 판정은 승인 근거 접수 또는 변경 요청이다. 운영 게이트 전이는 목적지 권한·버전 대조 단계에서 다룬다. |
| `workday.closed` | 이벤트 → 입력 순서별 일지 행(`includes_entry`), 행 → 행에 기록된 사건(`about_case`)·해당 사건의 근거(`cites`)·업무일지 초안(`contributes_to`). 같은 사건을 하루에 여러 번 기록하면 행은 각각 보존된다. |
| `needs_input` | 판정을 `waiting_for_input`으로 두고 결과 → 누락 필드(`requires`)를 기록한다. 누락된 대상을 참조하는 증거·검토 관계는 보완 후 생성한다. |
| `duplicate` · `blocked` | 로컬 처리 결과와 사유를 기록한다. 중복 건의 업무 사실을 재생성하지 않는다. 같은 버전의 내용이 충돌하면 사건 귀속을 유보한다. 식별이 불가능한 입력에서는 차단 범주만 만들며, 개별 시도 횟수는 라우터의 출력 건수로 센다. |

그래프에는 본문·누구의 연락처인지·업무일지 문장·재현 절차·학습 문장을 복사하지 않는다. 각 분류에서 검증된 식별자는 연결을 위해 그대로 남는다. `personal` 결과와 추적 화면은 개인 출력 경로에 둔다. 회사 원문과 내부 식별자를 공개 예제에 가져오지 않는다.

## 재현

이 디렉터리에서 `node build.mjs`로 기본 캔버스를 생성하고 `node --test route.test.mjs ontology.test.mjs`로 10개 분기의 그래프 참조 무결성, 생성된 n8n 코드와 Node 결과 일치, 사건 간·분류 간 격리, 일지 행 연결, 중복·충돌·거절 처리 및 기존 라우팅을 점검한다. 실제 n8n 재생과 검토 화면 여는 방법은 [재생 안내](README.md)를 따른다.
